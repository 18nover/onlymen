# OnlyMen Org Agents — Archive

This is an archived snapshot of the 13-agent AI engineering organization that
previously ran on the elizaOS framework in `eliza/packages/org/`. The `eliza/`
directory has been removed while other options for running these agents are
evaluated; the full agent definitions, knowledge base, shared standards, and
tooling source are preserved here for reference.

- [`AGENTS.md`](AGENTS.md) — the roster spec (naming/personality requirements, team structure) this org was built to
- [`ENGINEERING_OFFICE.md`](ENGINEERING_OFFICE.md) — the archived local control-plane doc (console, approval workflow)
- `*.md` (this directory) — one profile per agent, regenerated by [`bin/agents.ts`](../../bin/agents.ts) from `characters/*.json`
- `characters/` — raw agent configs: bio, full system prompt, personality, topics, style
- `knowledge/<agent>/` — per-agent domain grounding docs
- `shared/` — org-wide standards (coding, security, review process, escalation matrix, etc.)
- `skills/` — skill playbooks referenced by agent reviews and linked from each agent doc
- `tools/`, `package.json`, `biome.json` — the elizaOS-era chat-ui control
  plane and package config. **Inert** — depends on `@elizaos/core` and the
  bun/elizaOS runtime, neither of which exist in this repo anymore. Kept
  verbatim as a reference for a future runtime.

The old `bin/org` CLI and `scripts/generate-agent-docs.ts` /
`validate-characters.ts` (which needed Bun and `@elizaos/core`) were removed
in favor of `bin/agents.ts` at the repo root - a plain Node reimplementation
of the parts that don't need a live agent server:

```bash
node bin/agents.ts list        # or: make agents-list
node bin/agents.ts docs        # or: make agents-docs     (regenerates *.md below)
node bin/agents.ts validate    # or: make agents-verify   (also runs in `make lint`)
```

`org`'s server-lifecycle, chat, and board commands (`start`/`say`/`board`/
`assign`/`task`/`review`/`escalate`) have no equivalent - they talked to the
elizaOS agent runtime on `:2139`, which no longer exists.
